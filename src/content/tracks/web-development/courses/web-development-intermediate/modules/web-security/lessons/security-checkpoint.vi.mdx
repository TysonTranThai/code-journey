Checkpoint này chấm _phán đoán_ bảo mật ở dạng chạy được: phân loại code dễ tổn thương, ghép phòng thủ với mối đe dọa, và mã hóa/kiểm tra đúng — đúng những phán quyết bạn sẽ đưa khi review pull request thật.

## Suy nghĩ như người phòng thủ

Kiến thức bảo mật chỉ thành kỹ năng khi bạn nói được _ranh giới ở đâu_ và
_cái gì bảo vệ nó_. Các tình huống trong checkpoint — input được in lại, câu
query ghép chuỗi, phân quyền chỉ ở client — là bốn đến năm lỗi đứng sau phần
lớn các vụ rò rỉ thật. Gọi tên chúng, sửa chúng, và giải thích bản sửa trong
một câu; câu đó mới là thứ reviewer thực sự đọc.

## Câu một nhịp của người phòng thủ

Với mỗi tình huống, sản phẩm bàn giao là một câu duy nhất: "rủi ro là X, ranh
giới chặn nó là Y." Nói được điều đó về input được in lại (XSS, chặn bằng
output encoding cộng CSP), câu query ghép chuỗi (injection, chặn bằng câu lệnh
tham số hoá), check phân quyền chỉ ở client (broken access control, chặn bằng
phân quyền phía server). Nếu bạn nói được những câu đó mà không cần ghi chú,
module đã vào đúng chỗ.
