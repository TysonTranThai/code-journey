HTML là nội dung, CSS là giao diện. **JavaScript là hành vi** — ngôn ngữ lập trình duy nhất mà trình duyệt chạy nguyên bản. Mọi thứ tương tác trên web — autocomplete, kéo-thả, tỷ số trực tiếp, kiểm tra biểu mẫu — đều là JavaScript thay đổi trang sau khi nó tải xong.

## Nó chạy ở đâu

Trình duyệt tải tệp `.js` của bạn về và thực thi nó, từ trên xuống, bên trong trang. Cùng ngôn ngữ đó cũng chạy trên server (Node.js) — đó là cách Code Journey chấm các thử thách của bạn — nhưng trong module này, trình duyệt là nhà.

## Lệnh đầu tiên của bạn: console.log

```js
console.log("Hello, web!");
```

`console.log(...)` in các giá trị ra **console** — một bảng điều khiển có sẵn trong mọi trình duyệt (mở bằng F12 hoặc chuột phải → Inspect → Console). Dân lập trình sống trong console: đó là nơi bạn kiểm tra code của mình thực sự đã làm gì. Trong các thử thách này, máy chấm đọc output console của bạn, nên `console.log` là cách code của bạn trò chuyện với các test.

## Câu lệnh kết thúc bằng dấu chấm phẩy (thường vậy)

Một **câu lệnh (statement)** là một chỉ thị. Các style guide không thống nhất, nhưng các thử thách này kỳ vọng một dấu chấm phẩy ở cuối mỗi câu lệnh:

```js
console.log("one");
console.log("two");
```

## Chú thích

Văn bản sau `//` bị trình duyệt bỏ qua — ghi chú cho con người:

```js
// chào người học
console.log("Welcome!");
```

## Lỗi là chuyện bình thường

Gõ `consolelo.g("x")` và console hiện một **error** màu đỏ kèm số dòng. Lỗi không phải thất bại — chúng là trình duyệt nói chính xác nơi cần nhìn. Mọi dân chuyên nghiệp đọc lỗi hàng chục lần mỗi ngày.

## Bạn đã học được gì

- JavaScript = hành vi; nó chạy trong trình duyệt sau khi trang tải xong
- `console.log` in giá trị; console là vòng phản hồi của bạn
- Các câu lệnh được phân tách bằng dấu chấm phẩy; `//` bắt đầu một chú thích
- Lỗi chỉ vào vấn đề — hãy đọc chúng

**Tiếp theo:** lưu giá trị với biến.
