Bạn đã dùng hàm rồi: `console.log` và `name.toUpperCase()` là những hàm do người khác viết. Giờ đến lượt bạn viết hàm của riêng mình.

## Khai báo một hàm

```js
function greet(name) {
  return "Hello, " + name + "!";
}

greet("Ada"); // "Hello, Ada!"
greet("Grace"); // "Hello, Grace!" — cùng công việc, đầu vào khác
```

Giải phẫu:

- `function` — từ khóa mở đầu một khai báo
- `greet` — tên (giống động từ: hàm _làm_ việc)
- `(name)` — **tham số (parameter)**: các đầu vào có tên mà hàm kỳ vọng
- `return` — trả một giá trị về cho whoever gọi hàm

## Tham số vs đối số

Tham số là các tên trong định nghĩa; **đối số (argument)** là các giá trị thực được truyền khi gọi:

```js
function add(a, b) {
  // a, b là tham số
  return a + b;
}

add(2, 3); // 2 và 3 là đối số → 5
```

## return kết thúc hàm

Ngay khoảnh khắc `return` chạy, hàm đã xong — code bên dưới bị bỏ qua. Một hàm không có `return` trả về `undefined`:

```js
function logTwice(msg) {
  console.log(msg);
  console.log(msg);
} // trả về undefined — làm việc, nhưng không trả gì về

function double(n) {
  return n * 2;
} // trả 4 về khi được gọi với 2
```

Cả hai phong cách đều chính đáng: _làm một việc_ (log, lưu, cập nhật trang) so với _tính một thứ_ (trả về nó). Máy chấm trong khóa học này thường gọi hàm của bạn, nên return là cách bạn trao kết quả.

## Vì sao hàm quan trọng

Hàm cho phép bạn viết logic **một lần** và tin tưởng nó ở khắp nơi. Sửa một bug bên trong `greet` và mọi nơi gọi đều được sửa. Chúng cũng là cách các chương trình lớn giữ được sự dễ đọc: một hàm có tên tốt là một dòng tóm tắt những gì nó làm.

## Bạn đã học được gì

- Khai báo với `function name(parameters) { ... }`
- `return` trao một giá trị về và kết thúc hàm
- Không return → `undefined`
- Viết logic một lần, gọi nhiều lần

**Tiếp theo:** một cú pháp ngắn hơn cho hàm, và cách phạm vi hiển thị của biến hoạt động.
