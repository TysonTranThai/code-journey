Một trang web nằm trên laptop của bạn là một buổi diễn tập. **Triển khai (deployment)** sao chép nó lên một server để cả thế giới có thể ghé thăm. GitHub Pages triển khai thẳng từ một repository — miễn phí, và hoàn hảo cho các trang tĩnh bạn xây trong khóa học này.

## Triển khai một repo với Pages

1. Push dự án của bạn lên GitHub (bài học trước)
2. Repo → Settings → Pages
3. Source: "Deploy from a branch" → nhánh `main`, thư mục `/ (root)`
4. Save — trong vòng vài phút site của bạn hoạt động tại `https://your-name.github.io/my-site/`

Mỗi lần push vào main sẽ tự động triển khai lại. Deployment trở thành một hệ quả phụ của việc commit — thói quen đó mở rộng được suốt đến các đội chuyên nghiệp.

## Điều gì hoạt động trên Pages — và điều gì không

Hoạt động: HTML, CSS, và JavaScript phía client (mọi thứ từ Module 1–4).

Không hoạt động: code phía server. Pages phục vụ tệp; nó không thể chạy một cơ sở dữ liệu hay một server Node. Đó là việc của các nền tảng hosting đầy đủ — một bước tiếp theo tự nhiên sau khóa học này, không phải một điều bí ẩn.

## Danh mục kiểm tra triển khai (bắt các lỗi kinh điển)

- **Đường phân biệt chữ hoa chữ thường** trên server: `Logo.PNG` ≠ `logo.png`
- Dùng **đường dẫn tương đối** (`./styles.css`) — các đường dẫn tuyệt đối như `/Users/ada/...` chỉ tồn tại trên máy của bạn
- Test trong cửa sổ ẩn danh/riêng tư — cache hay nói dối

## Bạn đã học được gì

- Deployment = sao chép site của bạn lên một server mà cả thế giới chạm tới được
- GitHub Pages triển khai từ một nhánh và triển khai lại sau mỗi lần push
- Hosting tĩnh phục vụ tệp; server và cơ sở dữ liệu cần hosting đầy đủ
- Đường dẫn tương đối + chữ hoa chữ thường chính xác = hai bug triển khai kinh điển

**Tiếp theo:** khép lại module với một checkpoint và một lần công bố thật.
