Git là cục bộ; **GitHub** lưu trữ các Git repository trên mạng. Bản sao trực tuyến được gọi là **remote**. Công khai repo của bạn mang lại bản sao lưu, một portfolio, và khả năng cộng tác — mọi đơn xin việc bạn từng nộp đều bắt đầu bằng một liên kết đến GitHub của bạn.

## Kết nối và push

Sau khi tạo một repo rỗng trên github.com (trang web hiện cho bạn chính xác các lệnh này):

```text
git remote add origin https://github.com/ada/my-site.git
git push -u origin main
```

- `origin` là biệt danh theo quy ước cho remote của bạn
- `push` tải các commit lên; `-u` ghi nhớ cặp ghép nối để những lần push sau chỉ là `git push`

## Chu trình hằng ngày với một remote

```text
git pull            # lấy + hợp nhất mọi thứ mới từ remote
...làm việc, add, commit...
git push            # chia sẻ các commit của bạn
```

`clone` là chiều ngược của remote-add: nó tải về một repo có sẵn cùng toàn bộ lịch sử — `git clone <url>` là cách bạn tham gia bất kỳ dự án nào.

## README, issues, pull request

- **README.md** — trang chủ của repo: nó là gì, cách chạy nó
- **Issues** — một danh sách việc cần làm gồm các bug và ý tưởng
- **Pull request (PR)** — "làm ơn hợp nhất nhánh của tôi": bước xem xét-và-thảo luận mà mọi đội nhóm đều dùng. Trên repo của chính mình, hãy mở PR cho chính mình để luyện tập; đọc diff là một kỹ năng đáng xây dựng sớm.

## Bạn đã học được gì

- Remote là repo của bạn được lưu trữ trực tuyến; `origin` theo quy ước
- `push` tải lên, `pull` tải xuống, `clone` bắt đầu mới tinh
- README, issues, và PR là cách các dự án thật giao tiếp

**Tiếp theo:** đưa một trang web thật lên internet — GitHub Pages.
