    2. `src/server/actions/auth.ts` ("use server"): three zod-validated actions —
       - `register(prevState, formData)`: validates name/email/password (password ≥ 10 chars), lowercases email, rejects existing email with a GENERIC message ("If this email can be registered, follow the instructions") to avoid enumeration; on success creates user (role student, bcrypt hash) + profile row, then signs the user in via credentials `signIn` from the shared auth config.
       - `requestPasswordReset(prevState, formData)`: validates email format; looks up user; ALWAYS returns the same generic success regardless of existence; when the user exists, generates 32 random bytes (node:crypto randomBytes), stores sha256 hex in password_reset_tokens with 1-hour expiry, and logs the raw link (`http://localhost:3000/reset/<token>`) to the server console (dev transport — D-05; no nodemailer).
       - `consumePasswordReset(prevState, formData)`: validates password; hashes incoming raw token with sha256, finds the unexpired, unused row; on success updates the user's passwordHash, marks usedAt, and invalidates all existing sessions for that user (delete accounts' sessions rows where userId — JWT sessions cannot be server-revoked, note this in code comments; delete sessions rows is best-effort).
       - Use React 19 `useActionState`-compatible signatures `(prevState, formData) => state` and typed field errors; revalidate nothing user-facing.
    3. `tests/unit/reset-token.test.ts` (no DB): test the token helper functions in isolation (hash determinism, expiry math, constant-shape error objects) by extracting them to `src/lib/auth/reset-token.ts` and testing that module.
