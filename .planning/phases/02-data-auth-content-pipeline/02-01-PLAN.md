<task type="auto">
  <name>Task 2: Identity schema + generated migrations</name>
  <files>src/lib/db/schema.ts, src/lib/db/migrations/*</files>
  <read_first>docs/DATA-MODEL.md, .planning/phases/02-data-auth-content-pipeline/02-CONTEXT.md (D-02, D-04, D-06, D-11, D-12)</read_first>
  <action>
    Define Drizzle pgTables exactly matching what the Auth.js Drizzle adapter expects plus project extensions:
    1. `users`: id (text, primaryKey, default random uuid via `crypto.randomUUID()` in `$defaultFn`), name text, email text (notNull, unique), emailVerified timestamp(with timezone), image text, role userEnum ("student" | "admin") notNull default "student", createdAt/updatedAt timestamps notNull defaultNow.
    2. `accounts`: provider, providerAccountId, type, plus standard adapter fields; composite PK (provider, providerAccountId); userId text notNull references users.id onDelete cascade; index on userId.
    3. `sessions`: sessionToken text PK, userId notNull references users cascade, expires timestamp notNull; index on userId. (Present for future database-session providers; unused by the JWT strategy.)
    4. `verification_tokens`: identifier + token composite PK, expires notNull.
    5. `password_reset_tokens`: id uuid PK, tokenHash text notNull unique (sha256 hex of the raw token — raw tokens are NEVER stored), userId notNull references users cascade, expiresAt notNull, usedAt timestamp nullable; index on userId.
    6. `profiles`: userId text PK references users.id cascade, displayName text notNull, bio text, avatarUrl text; 1:1 with users.
    7. Export relations where useful (users→accounts/sessions/profile). Use pgEnum for role. NO curriculum, progress, submission, or discussion tables — those are later phases; the DB stores user-generated state only (docs/DATA-MODEL.md principle 2).
    Then run `pnpm db:generate` and commit the generated SQL in src/lib/db/migrations/.
  </action>
