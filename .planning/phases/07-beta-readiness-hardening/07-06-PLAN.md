# Plan 07-06: Mobile/Tablet Challenge Editor Render Fix

## Objective

Make Monaco render (non-zero, painted, editable, runs) on the tabbed mobile/tablet layout
across 1440/1280/1024/768/430/390/375px. Currently the editor's bounding box is 0×0 so the
core challenge loop is unusable below the desktop breakpoint.

## Root cause (verified)

- `src/components/challenge/ChallengeWorkspace.tsx`: the mobile branch is
  `<div className="lg:hidden">` (line 219) with **no definite height**.
- `src/components/challenge/MobileTabs.tsx`: root is `flex h-full min-h-0 flex-col`; each
  panel is `role="tabpanel" ... className="min-h-0 flex-1 overflow-auto pt-3"` and is
  rendered with `hidden={tab.id !== active}`.
- `src/components/challenge/CodeEditor.tsx`: wrapper `h-full min-h-[16rem]`, inner
  `<Editor height="100%" ... automaticLayout={true}>`.
- **Chain:** `lg:hidden` wrapper (no height) → MobileTabs `h-full` (resolves to 0) → panel
  `flex-1` (0) → CodeEditor `h-full`/`min-h` (0) → Monaco initializes at 0×0 while its
  panel is `display:none` (it mounts because **all** panels render eagerly; the initial
  active tab is `instructions`). `automaticLayout`'s ResizeObserver can't recover because
  the container chain has no intrinsic size at mount.

## Fix strategy

1. **Lazy-mount** the active tab panel's content (render only the active tab's children), so
   Monaco mounts only when the Code tab is selected and visible with real dimensions.
2. Give the mobile workspace a **concrete height** so `h-full`/`flex-1`/`min-h` resolve:
   set a height on the `lg:hidden` branch (or the MobileTabs root), e.g.
   `min-h-[60vh]` and/or `flex-1` within a definite-height parent.
3. Keep the draft in the parent (`useDraft`) so switching tabs preserves the typed code.

## Current implementation

- All three panels are always mounted; inactive ones are `hidden`.
- The mobile wrapper has no height.

## Files likely affected

- `src/components/challenge/ChallengeWorkspace.tsx` — add a definite height to the mobile
  branch.
- `tests/e2e/mobile-editor.spec.ts` (new).

## Implementation steps

1. In `MobileTabs`, render only the active tab's panel content: replace the always-mount
   map with a conditional that renders the active panel. Ensure `role="tablist"`/`tab`/`tabpanel`
   semantics and `aria-selected`/`aria-controls` are preserved, and that switching tabs
   updates focus/`hidden` correctly.
2. In `ChallengeWorkspace`, change the mobile wrapper to a definite height, e.g.
   `<div className="lg:hidden min-h-[60vh] flex flex-col">` and ensure `MobileTabs` fills it.
3. In `CodeEditor`, keep `height="100%"` and `automaticLayout`; the definite parent now makes
   size resolve. Optionally trigger `editor.layout()` on mount via `onMount` after a
   `requestAnimationFrame` as a belt-and-suspenders.
4. Confirm draft persistence (value prop from `useDraft`) is unaffected by unmount/remount.

## Tests (deterministic verification; E2E at the widths above)

New `tests/e2e/mobile-editor.spec.ts` asserting all of:
- The editor **exists** (`.monaco-editor` present) and has **non-zero** width *and* height
  (`getBoundingClientRect()` w>0, h>0).
- It **paints**: the `.view-line` text is visible (offsetParent not null, bounding box > 0).
- It **accepts keyboard input**: type into the hidden editor textarea / `.view-lines` and
  assert the value updates.
- It **preserves code**: after switching Code → Instructions → Code, the typed value remains
  (draft).
- It **runs code** and **displays results**: run, poll, assert a verdict is shown.

Run the assertions at **1440 / 1280 / 1024 / 768 / 430 / 390 / 375** (a parameterized spec).
