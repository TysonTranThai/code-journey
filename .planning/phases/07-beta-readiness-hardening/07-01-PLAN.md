# Plan 07-01: Grade-Integrity Heredoc Delimiter Fix

## Objective

Prevent a student from forging a passing verdict by escaping the fixed heredoc
delimiter. The current sandbox cannot be escaped from, but grading integrity can be
violated.

## Threat → behavior

- **Threat:** a submission containing the literal line `CODEJOURNEY_EOF` terminates the
  `cat > solution.js << '<delim>'` heredoc early. The remaining submission text is then
  interpreted by `sh` as commands (running as the sandbox user inside the container).
- **Existing behavior:** `src/workers/sandbox.ts` `buildJobScript()` writes every test
  file and `solution.js` with the same constant `CODEJOURNEY_EOF`, and the marker the
  runner parses is `__TEST_RESULT__ <name> status=<n>` on stdout. Escaping the heredoc
  lets code echo a false `__TEST_RESULT__ ... status=0` line and get a **passed** verdict.
- **New behavior:** the delimiter is random per job and the submitted code/tests are
  rejected if they contain it, so a submission can never terminate the heredoc.
- **Why this prevents forgery:** with a machine-random per-job delimiter, the attacker
  cannot predict the delimiter to escape it; and because the submitted text is explicitly
  rejected if it matches the chosen delimiter, even a lucky guess is blocked. The student
  code is always written as *data* into `solution.js`, never interpreted by `sh`. Thus no
  marker can be injected into the sh-generated stdout beyond the genuine per-test echoes.

## Current implementation

- `src/workers/sandbox.ts`:
  - `const ... = "CODEJOURNEY_EOF"` inside `heredoc()` (hard-coded).
  - `buildJobScript(code, testFiles)` uses `heredoc("solution.js", code)` and
    `heredoc("test-<name>.mjs", buildTestFile(test))`.
  - Marker protocol emitted by `buildJobScript` (the `echo "__TEST_RESULT__ ..."` line).
- `src/workers/execute.ts` parses `__TEST_RESULT__ <name> status=<n>` from stdout.

## Files likely affected

- `src/workers/sandbox.ts` — generate a per-job delimiter; reject content containing it.
- `tests/integration/sandbox-isolation.test.ts` — add malicious-delimiter cases.

## Implementation steps

1. Add a deterministic-but-random delimiter generator, e.g.
   `function jobDelimiter(): string { return "CJ_EOF_" + randomBytes(12).toString("hex"); }`
   (from `node:crypto`).
2. Generate the delimiter once per `runSandboxed` call and thread it into `buildJobScript`.
3. Before building the script, reject if `code` or any test `code` string contains the
   delimiter: if it does, treat as a hard input error (return an `error`-ish result, never
   run). Alternatively append a defensive `printf ''` terminator — but rejection is the
   primary control; keep both: reject, and always use the random delimiter.
4. Make `buildJobScript` accept the delimiter param and use it in every heredoc literal;
   update the fixture test builders to pass a test delimiter.
5. Keep the marker protocol unchanged (`__TEST_RESULT__ <sanitized-name> status=<n>`).
   The test name is `sanitizeName(test.name)` from author content — safe.

## Tests

Add to the malicious-sample suite (same file as the existing isolation tests):

- Submit code whose text contains the *fixed* old delimiter `CODEJOURNEY_EOF` but NOT the
  (random) generated one → must still be treated as data, verdict reflects the real tests
  (i.e., fails for broken code, passes for correct code), and no forged pass.
- A crafted submission that tries to echo `__TEST_RESULT__ <test> status=0` must NOT yield
  a passing verdict when the real tests fail.
- Regression: a **genuine** passing solution still returns `passed`.
- Boundary: generating the delimiter and asserting it differs between two `runSandboxed`
  calls and that content containing the delimiter is rejected.

## Rollback

The change is contained to `sandbox.ts`; revert reverts to constant delimiter. No schema
or data migration. Safe to revert independently.

## Security implications

Closes a grade-integrity hole without weakening the isolation baseline. Reinforces that
the sandbox never executes the submitted text as shell. No new secrets; delimiter is
ephemeral per job and never logged.
