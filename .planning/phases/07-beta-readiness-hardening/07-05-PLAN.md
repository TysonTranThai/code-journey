# Plan 07-05: Accurate Product Copy + Stale-Messaging Guard

## Objective

Remove misleading "coming in a future phase" copy that denies shipped features, and prevent
regression with an automated guard. Keep internal documentation and legitimate future-phase
language untouched.

## Threat → behavior

- **Threat:** a first-time visitor is told the product's headline features (auto-graded
  challenges, progress tracking, AI mentor) are still "in upcoming phases," when they ship.
- **Existing behavior (verified):**
  - `src/app/page.tsx:31-33`: "Curriculum browsing is live. Auto-graded challenges, progress
    tracking, and the AI mentor ship in upcoming phases."
  - `src/app/(learn)/learn/page.tsx:24`: "...save progress (arriving in a later phase)."
  - `src/app/(learn)/learn/page.tsx` metadata `description`: "...HTML, CSS, JavaScript, and
    more" — over-promises curriculum that does not yet exist.
- **New behavior:** public pages describe what actually exists now and link to it; they no
  longer claim features are pending. Legitimate future-feature/forward-looking language
  only appears where a feature genuinely does not exist yet (e.g., real email delivery,
  OAuth, multi-language runs) and is worded as a plan, not a denial of shipped work.

## Current implementation

- `src/app/page.tsx` and `src/app/(learn)/learn/page.tsx` contain the stale lines (verified).

## Files likely affected

- `src/app/page.tsx` — replace the "ship in upcoming phases" line with a truthful summary +
  a link to `/learn` and the dashboard/mentor where appropriate.
- `src/app/(learn)/learn/page.tsx` — replace "arriving in a later phase"; tighten the
  metadata description to what exists (drop "CSS, JavaScript" until curriculum ships).
- `tests/unit/stale-copy.test.ts` (new) — guard against regression.

## Implementation steps

1. Rewrite the homepage callout to reflect shipped capability, e.g.:
   "Learn in structured lessons, practice in auto-graded challenges, track your progress,
   and get mentor hints that teach instead of solving." Link to `/learn`.
2. Write the /learn intro for current reality, e.g.:
   "Create a free account to save your progress, earn achievements, and ask the mentor."
3. Tighten the `/learn` metadata `description` to the actual curriculum.
4. Add a guard test that scans the source of all public-ish route pages
   (`src/app/**/page.tsx`, excluding API/`(auth)` where noted) and fails if any of the
   stale phrases appear. Anchor phrases: `"upcoming phases"`, `"arriving in a later phase"`,
   `"coming soon"`, `"will ship"`. Also assert the homepage includes an affirmative mention
   of auto-graded challenges / progress / mentor so we do not regress to silence.

## Tests

- `tests/unit/stale-copy.test.ts`: scans route pages; asserts no stale phrases; asserts
  affirmative feature mention remains.

## Verification

## Rollback

Copy-only; no structural change. Reverting restores the old wording.

## Security implications

None. (Do not remove legitimate "planned/deferred" language in `docs/SECURITY.md` or `.planning/*`; the guard is scoped to user-facing route pages.)
